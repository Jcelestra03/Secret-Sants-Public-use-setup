Setup guide

Set it up in 8 steps

Tick each step as you finish it. Your progress is saved in this browser and shown in the bar at the top. The screen illustrations are simplified, so the real Firebase and GitHub pages may look slightly different.

Before you start, download the project: on the GitHub repository, click Code → Download ZIP and unzip it. You'll edit index.html with any text editor (Notepad works).
1

Create a Firebase project ~2 min

Firebase is Google's free app backend. It stores the event, wishlists and matches.

  1. Open the Firebase console and sign in.
  2. Click Create a project.
  3. Name it, for example secret-santa. Firebase adds a few characters to make your project ID.
  4. Turn Google Analytics off (not needed) and click Create project.

2

Connect the website to Firebase ~3 min

  1. On Project Overview, click the Web icon </>.
  2. Give it a nickname and click Register app. Leave "Firebase Hosting" unticked.
  3. Copy the values inside firebaseConfig.
  4. In index.html, replace each PASTE_… value with yours. Keep the quotes.
Is it safe for this to be public? Yes. Every Firebase website sends this config to the browser. It identifies your project but isn't a password. Step 5 is what protects the data.

  2. Open the Sign-in method tab.

5

Add the security rules ~1 min

Production mode blocks everything, so the site won't work until you publish these rules.

  1. In Firestore Database, open the Rules tab.
  2. Delete everything in the editor.
  3. Click Copy on the box here (it's the same as firestore.rules in the project) and paste.
  4. Click Publish.
These rules keep strangers out and only allow the data the site uses. Read Security to see what they don't cover.
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    function signedIn() {
      return request.auth != null;
    }

    match /event/{id} {
      allow read: if signedIn() && id == 'main';
      allow write: if signedIn() && id == 'main'
        && request.resource.data.keys().hasOnly(['title', 'budget', 'date', 'drawn', 'revealed']);
    }

    match /people/{code} {
      allow read, delete: if signedIn();
      allow create, update: if signedIn()
        && request.resource.data.keys().hasOnly([
             'name', 'admin', 'claimed', 'done', 'bought', 'kindness',
             'answers', 'codename', 'giveTo'
           ])
        && request.resource.data.name is string
        && request.resource.data.name.size() <= 60;
    }

    match /chats/{code} {
      allow read: if signedIn();
      allow write: if signedIn()
        && request.resource.data.keys().hasOnly(['items'])
        && request.resource.data.items is list
        && request.resource.data.items.size() <= 4;
    }

    match /{document=**} {
      allow read, write: if false;
    }
  }
}

6

Make it yours optional

All the settings are near the top of the <script> in index.html.

  • COUPLES: pairs who shouldn't draw each other. The names must match the names you type when you create the event.
  • DEX: the Pokémon code names. The number is the Pokédex number, which is used for the picture. Add at least one per person.
  • BONUS: an optional popup asking people whether they'd like to gift your pets or kids too.
  • Q: the questionnaire questions and answer choices.
const COUPLES=[
  ["Alex","Jordan"],   // these two won't match
  ["Sam","Taylor"],
];

const DEX={"Pikachu":25,"Eevee":133,"Snorlax":143, …};

const BONUS={
  enabled:true,                // show the popup
  title:"Biscuit & Pepper",
  pics:[["bonus1.jpg","🐶","Biscuit"]]
};

7

Put it online ~5 min

Pick one. GitHub Pages is all clicks; Firebase Hosting uses a few commands and also uploads your rules.

  1. On GitHub, create a New repository and set it to Public.
  2. Click uploading an existing file, drag in your edited index.html (and any bonus images), then click Commit changes.
  3. Go to Settings → Pages. Set Source to Deploy from a branch, branch main, folder / (root), and click Save.
  4. Wait a minute or two. Your address appears at the top, for example your-name.github.io/secret-santa.
  5. In Firebase: Authentication → Settings → Authorized domains → Add domain, and add your-name.github.io.

8

Run your Secret Santa 🎄

Open your site yourself first. Whoever opens it while the database is empty becomes the organizer. Save the code it shows you; it's the only way back in as the organizer.

Someone lost their code? In the Organizer tab, click Reset login next to their name, then have them pick their name again. Their wishlist and match stay the same.

Under the hood

How the pieces fit

There's no server of your own. The page in each person's browser talks straight to Firebase.

chatspersonUp to 4 anonymous questions to that person, with answers
Security

Made for people who trust each other

This keeps the surprise from people who play fair, like a family or a group of friends. It won't stop someone determined to snoop, so here is exactly what is and isn't protected.

✅ Protected

  • People who never open the site can't read or write anything.
  • Only the three collections and the fields the site uses can be written.
  • Each question thread is capped at 4 messages.
  • The organizer screen never shows anyone's login code.

⚠️ Known limitations

  • The "Pick my name" screen loads every person's record, so anyone using the browser's developer tools can see all codes, wishlists and matches.
  • Your match is stored by their login code, so you could log in as them.
  • Organizer-only buttons are hidden in the browser, but the rules don't check who the organizer is.
  • Anonymous sign-in proves someone opened the site, not who they are.
How it could be hardened: a separate names-only list for "Pick my name", rules that let each person read only their own record, matches stored by a random ID, real sign-in for organizers, and a server-side draw with a Firebase Cloud Function so nobody sees all the matches.
Don't put addresses, phone numbers or passwords in wishlists, and delete the data after the event.
Troubleshooting

Something not working?

"Almost there. Paste your Firebase config…"
FIREBASE_CONFIG in index.html still has the PASTE_… placeholders. Go back to step 2.
"Could not reach the database"
Check that all six config values are pasted correctly (step 2), Anonymous sign-in is on (step 3), the database exists (step 4), and the rules are published (step 5). Press F12 and open the Console tab to see the exact error.
It works on my computer but not on GitHub Pages
Add your-name.github.io under Authentication → Settings → Authorized domains, and give GitHub a minute or two to update after each upload.
"Could not save. Check your Firestore rules."
Make sure you pasted the entire rules file and clicked Publish (step 5).
"Couldn't find a valid draw with those rules."
There are too many "can't match" pairs for the group size. Remove some pairs, or add more people.
A couple got matched together
The names in COUPLES must match the names typed on the setup screen (capital letters don't matter).
I lost the organizer code
In the Firebase console, open Firestore Database → Data → people and find the document whose admin field is true. Its document ID is your code.
How do I start over next year?
In Firestore Database → Data, delete the event, people and chats collections (⋮ menu → Delete collection). The site shows the setup screen again.
Does this cost anything?
No. Firebase's free Spark plan easily covers a family-sized group, with no credit card, and GitHub Pages is free for public repositories.
